## ۲. بخش‌های کتاب که تاکنون مطالعه شده‌اند

بخش‌های ۲.۳ و ۲.۴ کتاب را مطالعه و بررسی کرده‌ایم.

### بخش ۲.۳: مهندسی پرامپت (Prompt Engineering)

موضوعات بررسی‌شده:
- تفاوت پیام کاربر (`user`) و دستورالعمل سیستم (`system`).
- نقش System Prompt در تعیین رفتار، وظیفه و قالب پاسخ مدل.
- اهمیت دستورالعمل‌های روشن و محدودیت‌های آن‌ها.
- اینکه پرامپت مناسب به‌تنهایی تضمین نمی‌کند مدل همیشه پاسخ درست بدهد.

### بخش ۲.۴: ارزیابی مدل و آزمایش GAIA

موضوعات بررسی‌شده:
- هدف بنچمارک GAIA و ارزیابی توانایی مدل‌ها در حل مسائل.
- ساختار پرسش‌ها و سطوح دشواری.
- مدل داده Pydantic برای خروجی ارزیابی، از جمله `GaiaOutput`.
- توابعی مانند `get_provider`، `solve_problem`، `is_correct`، `evaluate_gaia_single` و `run_experiment`.
- تفاوت پاسخ‌دادن مدل با حل صحیح مسئله.
- اهمیت ابزارها برای مسائل نیازمند اطلاعات به‌روز، جست‌وجوی وب یا خواندن فایل.

اکنون می‌خواهم کتاب را از **بخش بعدی پس از ۲.۴** ادامه دهم. در گفت‌وگوی بعدی، ابتدا از من بخواه متن بخش بعدی کتاب را ارسال کنم؛ عنوان یا محتوای آن را حدس نزن.

## ۳. برنامه عملی Python که ساخته‌ایم

مسیر پروژه:

`C:\Users\Ghassem BAKHTIARI\Desktop\build-an-ai-agent-from-scratch\main.py`

محیط اجرا: VS Code در ویندوز.

مدل و سرویس مورد استفاده:
- مدل: `openai/gpt-5-mini`
- API endpoint: `https://1xai.ir/v1`
- کلید API از متغیر `XAI_1_API_KEY` در فایل `.env` خوانده می‌شود.
- فراخوانی مدل با `litellm.acompletion` انجام می‌شود.

برنامه فعلی شامل این اجزاست:

- `SYSTEM_PROMPT`: تعریف دستورالعمل مدل برای پاسخ‌گویی به مسائل حسابی.
- `call_llm()`: ارسال درخواست به مدل زبانی.
- `is_correct()`: مقایسه پاسخ مدل با جواب مورد انتظار.
- `build_questions()`: ساخت ۱۰۰ سؤال جمع، از `1 + 1` تا `100 + 100`.
- `run_sequential()`: اجرای درخواست‌ها به‌صورت ترتیبی.
- `run_concurrent()`: اجرای درخواست‌ها به‌صورت هم‌زمان.
- `summarize_results()`: محاسبه تعداد درخواست‌های موفق، خطاها، پاسخ‌های صحیح و زمان اجرا.
- `print_comparison()`: مقایسه عملکرد دو روش.
- `main()`: مدیریت اجرای آزمایش‌ها.

## ۵. مفاهیم Python که با آزمایش عملی یاد گرفته‌ایم

### `async` و `await`
برای تعریف و اجرای عملیات ناهم‌زمان، به‌خصوص درخواست‌های شبکه‌ای که زمان انتظار دارند.

### `asyncio.gather()`
برای مدیریت اجرای چند وظیفه ناهم‌زمان و جمع‌آوری نتایج آن‌ها.

### `asyncio.Semaphore(10)`
برای محدودکردن تعداد درخواست‌هایی که هم‌زمان وارد بخش محافظت‌شده می‌شوند.

### `time.perf_counter()`
برای اندازه‌گیری زمان سپری‌شده اجرای برنامه.

### ارزیابی خروجی
تفاوت میان دو مفهوم را بررسی کرده‌ایم:
- Request Success: آیا درخواست API پاسخ داده است؟
- Task Success / Correctness: آیا پاسخ با جواب صحیح مطابقت دارد؟
