## 2. کد فعلی main.py

نسخه فعلی برنامه به این شکل است:

```python
import os

from dotenv import load_dotenv
from litellm import completion


load_dotenv()


MODEL_NAME = "openai/gpt-5-mini"
API_BASE = "https://1xai.ir/v1"
API_KEY = os.getenv("XAI_1_API_KEY")


def ask_llm(question):
    return completion(
        model=MODEL_NAME,
        api_base=API_BASE,
        api_key=API_KEY,
        messages=[
            {
                "role": "user",
                "content": question,
            }
        ],
    )


def get_answer(question):
    try:
        response = ask_llm(question)
        return response.choices[0].message.content
    except Exception as error:
        print(f"Error while getting answer: {error}")
        return None


def main():
    question = input("Enter your question: ")

    answer = get_answer(question)

    if answer is not None:
        print("\nAnswer:", answer)
    else:
        print("\nCould not get an answer.")


if __name__ == "__main__":
    main()
```

### اجرای برنامه

```powershell
uv run python main.py
```

برنامه سؤال کاربر را دریافت می‌کند و پاسخ مدل را نمایش می‌دهد.

اتصال LiteLLM قبلاً با موفقیت آزمایش شده است؛ برای مثال، پاسخ سؤال درباره پایتخت فرانسه `The capital of France is Paris.` و پاسخ سؤال درباره پایتخت ژاپن `Tokyo.` بوده است.

## 3. مفاهیم برنامه‌نویسی که یاد گرفته‌ایم

### LiteLLM و رابط یکپارچه

LiteLLM امکان استفاده از یک رابط مشترک برای ارسال درخواست به مدل‌های زبانی مختلف را فراهم می‌کند.

نمونه:

```python
from litellm import completion

response = completion(
    model="openai/gpt-5-mini",
    messages=[
        {"role": "user", "content": "Hello!"}
    ],
)
```

نام مدل، آدرس سرویس و تنظیمات اتصال باید با سرویس انتخاب‌شده سازگار باشند. استفاده از LiteLLM به‌تنهایی تضمین نمی‌کند که همه مدل‌ها در هر سرویس واسط در دسترس باشند.

### تفکیک مسئولیت‌ها

- `ask_llm()`: ارسال درخواست به مدل.
- `get_answer()`: استخراج متن پاسخ و مدیریت خطا.
- `main()`: دریافت ورودی کاربر و نمایش نتیجه.
- `if __name__ == "__main__":`: اجرای تابع اصلی هنگام اجرای مستقیم فایل.

### ثابت‌های تنظیماتی

```python
MODEL_NAME = "openai/gpt-5-mini"
API_BASE = "https://1xai.ir/v1"
API_KEY = os.getenv("XAI_1_API_KEY")
```

این متغیرها تنظیمات اتصال را از منطق توابع جدا می‌کنند و تغییر تنظیمات را آسان‌تر می‌سازند.

### مدیریت خطا

در `get_answer()` از `try/except` استفاده شده است. در صورت بروز خطا، پیام خطا چاپ می‌شود و تابع `None` برمی‌گرداند.

این یک مدیریت خطای اولیه است؛ بعداً می‌توانیم خطاها را دقیق‌تر دسته‌بندی کنیم.

## 4. مطالب کتاب که مطالعه کرده‌ایم

### 4.1. Unifying providers with LiteLLM

مسئله این است که ارائه‌دهندگان مدل‌های زبانی رابط‌های متفاوتی دارند. LiteLLM یک رابط مشترک فراهم می‌کند تا بتوانیم در صورت پشتیبانی سرویس، مدل را با تغییر تنظیمات عوض کنیم.

### 4.2. Stateless APIs و مدیریت تاریخچه مکالمه

APIهای مدل زبانی معمولاً حافظه پایدار مکالمه ندارند. هر درخواست مستقل است، مگر اینکه برنامه پیام‌های قبلی را نیز ارسال کند.

برای حفظ تاریخچه، از یک فهرست به نام `messages` استفاده می‌کنیم:

```python
messages = []
```

پیام کاربر:

```python
messages.append({
    "role": "user",
    "content": "My name is Jungjun."
})
```

پاسخ مدل نیز باید به تاریخچه اضافه شود:

```python
messages.append({
    "role": "assistant",
    "content": assistant_message
})
```

سپس در درخواست بعدی، تاریخچه مرتبط همراه پیام جدید ارسال می‌شود.

نکته مهم: نگهداری تاریخچه بر عهده برنامه است، نه اینکه مدل خودبه‌خود تمام مکالمات قبلی را به یاد داشته باشد.

هرچه تاریخچه طولانی‌تر شود، تعداد توکن‌های ارسالی، هزینه و زمان پردازش می‌تواند افزایش یابد.

**وضعیت:** این مفهوم را مطالعه کرده‌ایم، اما هنوز کد مدیریت تاریخچه را به پروژه اضافه نکرده‌ایم.

### 4.3. Structured Output و Pydantic

پاسخ متنی برای انسان مناسب است، اما گاهی برنامه به داده‌ای با ساختار مشخص نیاز دارد.

Pydantic اجازه می‌دهد ساختار مورد انتظار را با کلاس تعریف کنیم:

```python
from pydantic import BaseModel


class ExtractedInfo(BaseModel):
    name: str
    email: str
    phone: str | None = None
```

در این مثال:

- `name`: رشته الزامی.
- `email`: رشته الزامی.
- `phone`: رشته اختیاری با مقدار پیش‌فرض `None`.

ساختارهای مشخص در مواردی مانند استخراج اطلاعات، اعتبارسنجی ورودی‌ها و فراخوانی ابزارها کاربرد دارند.

**وضعیت:** مفهوم مطالعه شده، اما هنوز در پروژه پیاده‌سازی نشده است.

### 4.4. Asynchronous calls

برای اجرای چند درخواست بدون انتظار متوالی، LiteLLM تابع `acompletion` را ارائه می‌کند.

مفاهیم اصلی:

- `async def`: تعریف تابع ناهمگام.
- `await`: انتظار برای نتیجه یک عملیات ناهمگام.
- `asyncio.gather()`: اجرای هم‌زمان چند coroutine و جمع‌آوری نتایج.
- `asyncio.Semaphore(10)`: محدود کردن تعداد عملیات هم‌زمان به ۱۰.
- `num_retries=3`: درخواست تلاش مجدد برای برخی خطاهای موقت.
- `return_exceptions=True`: امکان دریافت خطاهای هر عملیات به‌عنوان نتیجه، بدون لغو همه نتایج موفق.

اجرای ناهمگام به‌ویژه برای پردازش تعداد زیادی سؤال، مقایسه مدل‌ها و ارزیابی مجموعه‌ای از مسائل مفید است.

**وضعیت:** مفهوم مطالعه شده، اما هنوز کد ناهمگام را پیاده‌سازی نکرده‌ایم.
